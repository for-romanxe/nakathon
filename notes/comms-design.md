# 통신·전송 손실 설계 (논의, 2026-11-11)

회의 논의용. 사용자 확인: 아래 설명과 방향 OK (11/11). 미정 항목은 맨 아래.

## 사실 (출처 확인)
- DTN(지연·단절 허용 네트워크): 저장 후 전달. 표준 Bundle Protocol(RFC 9171, BPv7). NASA는 2026년 1월 이후 Near Space Network·Deep Space Network에서 DTN을 정식 서비스로 운영 (newspaceeconomy.ca 2026-10-08 보도).
- NASA HDTN 구현: BPv7, BPv6 custody transfer, LTP 수렴층 포함 (software.nasa.gov LEW-19897-2).
- DTN 저장 공간은 한정적이고, 번들이 쓸모 있는 기한 안에 도착한다는 보장은 없음.
- 화성 중계: Odyssey 하루 2~4회 패스, 2026년 2~5월 평균 107.3 Mb/일 (science.nasa.gov Mars Relay Network). Electra 무선은 궤도선이 지평선 근처면 속도를 낮춤.

## 일반 지식 (이번에 문서로 확인 안 함)
- 화성 편도 지연 4~22분, 왕복 최대 약 44분.
- 연결 중 손실: 비트 오류는 오류정정부호(FEC)가 처리, 남은 프레임 손실은 CFDP·LTP의 NAK 방식(다 보내고 빠진 목록만 재요청)으로 처리. 지상국 날씨(고주파 대역 비 감쇠), 창이 먼저 닫힘.

## 우리 시스템 방향
- 모델은 기기 안에서만 실행. 링크 끊김은 지상 검토 지연일 뿐, 판정·설명은 계속됨.
- 링크로 오가는 것: 요약·이벤트·경보 패킷(하향), 비행의 답장·모델/문서 업데이트(상향). 업데이트는 서명·버전 묶음, 끝까지 받아 검증 전엔 기존 버전 사용.
- 경보 단계 = 전송 우선순위: 경보 즉시 + 같은 창 안 2~3회 반복, 주의는 다음 창, 일일 요약은 정기 창, 원시 파형은 기기 보관·요청 시만.
- 요약 먼저(하루 몇 KB: z값·판정·이벤트·체크인), 원본은 요청 시.
- 모든 기록에 일련번호 + 해시, 추가 전용. 패킷마다 단독으로 읽히게. 지상은 빠진 번호만 다음 창에 재요청.
- 확인을 기다리며 멈추지 않음. 창 열리면 우선순위대로 전부 보내고 다음 창에서 빠진 목록 수신.
- 양방향 동일: 비행의 답장에도 번호·수신 확인. 화면에 보냄·지상 수신·답장 도착 표시.

## 미정
- "결과 대신 재현 재료 보내기"(입력 요약 + 규칙·모델 버전·시드 → 지상이 같은 파이프라인 재실행해 승무원 화면 재현·감사)를 발표 차별점으로 밀지.
- 해커톤 링크 시뮬레이터 범위: 창 열림/닫힘만 vs 연결 중 프레임 손실·재요청까지.
