# 평가셋 v2 (2026-11-14 행사 중 작성)

30문항(`../questions.json`)은 모든 구성이 거의 만점이라 차이를 가르지 못했다. v2는 문항을 늘리고, 시험용과 개발용을 나눴다.

| 파일 | 내용 | 시험(test) | 개발(dev) | 비교(cross) |
|---|---|---|---|---|
| `symptom.jsonl` | 증상 문장 → 코드. `expect`가 모두 있고 `forbid`가 없으면 맞음. `locations`는 부위 정답(표시용, 아래 따로 셈) | 60 | 30 | |

- **개발용**은 프롬프트나 설정을 고칠 때 본다. **시험용**은 구성을 정한 뒤 구성마다 한 번만 돈다. 시험용을 보고 프롬프트를 고치지 않는다.
- **비교용**은 "한국어 답 + 영어 문단" 10문항이다. 문단을 답할 언어로 미리 준 경우와 견주기 위한 것이다.
- 증상 문항 종류: 평이 · 돌려 말함 · 간접 · 부정("안 아파요") · 한영 혼용 · 여러 증상 · 증상 없음 · 헷갈리는 말("배고파 죽겠네", 남의 증상, 장비 이름) · 임무 상황.
- 급한 코드(가슴 통증·호흡 곤란·위기)는 따로 센다. 놓치면 안 되는 쪽이다.

## 어떻게 만들었나

- 문장은 AI(Claude)가 조사 노트의 용어를 참고해 새로 썼다. 기존 30문항·학습 템플릿·mock 문구와 같은 문장은 쓰지 않았다.
- 기분 문항은 다른 AI 채점자가 범위를 모른 채 다시 채점했다(1회, 36문항 모두 범위 안). 그 뒤 6문항은 표현을 다듬었고 작성자만 다시 확인했다. 같은 계열 모델의 1회 결과라 일치율로 쓰지 않는다.
- 설명 문항은 `ml/data/build_explain_cases.py`가 지식 문단(`ml/knowledge/`)으로 만든다. 지표와 상태의 짝은 문항을 만들기 위한 가정이다.
- **사람이 아직 읽지 않았다.** 한국어 문장의 자연스러움과 라벨은 한국어를 읽는 사람이 한 번 봐야 한다. 작성자가 덜 확신한 문항: 증상 ST-054 · SD-030(가슴 뻐근함), ST-056 · ST-059 · SD-026 · SD-028(간접적인 위기 표현), ST-017(부정된 위기 표현), 기분 MT-024 · MT-011 · MT-010 · MT-003.

## 부위 `locations` — 몸 화면 표시용 (2026-11-14 22시 추가)

증상 추출 응답에 `locations` 칸을 더했다(CONTRACT §5.5). 보고가 말한 부위를 몸 화면에 표시하는 데만 쓰고, 판정에는 쓰지 않는다. 증상 지시문이 바뀌었으므로 증상 문항을 두 구성으로 다시 쟀다(구성마다 1회, 같은 맥).

정답 붙이는 규칙:
- `locations`: 보고가 **말한** 부위. 모델이 모두 내야 한다. 두통·흉통·복통처럼 부위가 들어 있는 증상 말도 여기에 든다.
- `locations_allow`: 말하지는 않았지만 증상이 가리키는 부위(시야 → head, 숨 → chest, 구토 → abdomen, 어지럼 → head). 내도 되고 안 내도 된다.
- 좌우를 말하지 않은 팔·다리는 양쪽을 다 넣는다. 부정한 부위, 이미 나은 부위, 남의 부위, 비유는 넣지 않는다. 증상이 없으면 `[]`.
- 맞음 = 말한 부위를 모두 냈고, 허용한 것 말고는 더 내지 않았다. 증상 코드 점수와 따로 센다.
- 정답은 AI(Claude)가 붙였고 **사람이 읽지 않았다.** 부위를 말한 문항은 시험용 60개 가운데 22개, 개발용 30개 가운데 11개다.

| 항목 | 규칙 지시문 (학습 없음) | 규칙 지시문 + 어댑터 |
|---|---|---|
| 시험용 증상 (60) | 59/60 | 59/60 |
| 시험용 급한 코드 (18) | 18/18 | 18/18 |
| 시험용 부위 (60): 맞음 · 칸을 안 씀 | 54/60 · 0 | 54/60 · 0 |
| 그중 부위를 말한 문항 (22) · 말하지 않은 문항 (38) | 17/22 · 37/38 | 17/22 · 37/38 |
| 개발용 증상 (30) · 부위 (30) | 29/30 · 29/30 | 30/30 · 29/30 |
| 형식 오류 (개발 30 + 시험 60) | 0 | 0 |

읽을 때 알아 둘 것:
- **어댑터는 `locations`가 없는 라벨로 학습했는데도 지시문만으로 칸을 썼다.** 90문항에서 칸을 빠뜨린 적이 없다. 부위 점수는 학습 없는 구성과 같다.
- **시험용에서 틀린 6문항은 두 구성이 같다.** 5개는 부위를 빠뜨렸다: 코 막힘 2개(ST-015, ST-030), 어깨(ST-025), "속이 메슥"(ST-031), 좌우를 말하지 않은 forearm(ST-041). 1개는 "가슴이 벅차서"(ST-008)에 chest를 냈고, 이 문항은 증상 코드도 틀렸다. 좌우를 잘못 낸 문항은 없다.
- 개발용에서 틀린 1문항(SD-015)은 두 구성 모두 "양쪽 어깨가 아프다"에 back을 더 냈다.
- 지시문은 개발용 결과를 보고 두 번 고쳤다("오른쪽 눈"을 right_arm으로 낸 것, 좌우 없는 무릎을 빠뜨린 것). 시험용은 지시문을 확정한 뒤 구성마다 한 번 돌렸다.
- 칸이 하나 늘어 응답 시간 중앙값이 늘었다: 어댑터 1.8 → 2.2초, 학습 없음 2.5 → 3.0초.
- 바뀐 것은 증상 지시문뿐이라 기분·설명은 다시 재지 않았다. 위 결과 표의 증상 점수(57·59)는 `locations`를 넣기 전 지시문으로 잰 것이다.
- 모의 모델은 `locations`를 내지 않는다(키 없음 → 프론트가 문장에서 직접 찾는다).

## 백엔드가 실제로 보내는 입력으로 다시 잼 (2026-11-14 23:52 ~ 11-15 00:03)

| | 문장만 | 문장 + 측정값 (백엔드 입력) |
|---|---|---|
| 개발용 30 · 코드 맞음 | 30 | 30 |
| 개발용 30 · 부위 맞음 | 29 | 29 |
| 시험용 60 · 코드 맞음 | 59 | 59 |
| 시험용 60 · 부위 맞음 | 54 | 55 |
| 형식 오류로 버린 답 (90문항) | 0 | 0 |

- 코드 채점은 두 입력에서 같았다. 코드가 달라진 답은 90문항 중 5개다: 순서만 바뀐 것 2개, 코드가 하나 더 붙은 것 3개(SD-017에 `dizziness`, 위기 문항 ST-038·ST-049에 `low_mood`). 다섯 모두 채점은 그대로다.

| 대상 · 언어 | 입력 수 | 첫 실행에 5검사 통과 | 보류 | 서로 다른 문장 | 한 건 걸린 시간 |
|---|---|---|---|---|---|
| 조명 · 한국어 | 6 | 6 | 0 | 1 | 5.1~6.8초 |
| 일정 · 한국어 | 6 | 6 | 0 | 3 | 5.0~5.1초 |
| 조명 · 영어 | 6 | 6 | 0 | 3 | 4.3~4.6초 |
| 일정 · 영어 | 6 | 6 | 0 | 3 | 4.3~4.4초 |

- temperature 0 이라 같은 입력은 같은 답이 나온다. 그래서 반복하지 않고 수면·심박변이·심박 수치와 단계를 바꾼 입력 6개로 쟀다. 첫 입력이 #47 시연 수치 초안(수면 5.1시간, 심박변이 −2.5)이다. 입력 6개는 넓은 표본이 아니다.
- **문장은 수치를 따라 바뀌지 않는다.** 한국어 조명은 6개 입력에서 문장이 글자까지 같았고, 나머지도 낱말 한두 개만 달랐다. 이유 문장은 근거 문단에서 나오고 수치는 규칙이 쓰는 문장에 들어가는 구조라서 그렇다.
- 실패하는 길은 따로 한 번씩 실행해 봤다. `MODEL_TIMEOUT=0.5`로 시간 초과를 내면 0.5초 뒤 보류로 끝나고 근거 문단 id 는 그대로 나왔다. 서버가 없는 주소를 주면 바로 보류로 끝났다. 근거 파일이 없거나 표에 없는 대상이면 모델을 부르지 않는다(테스트).
- 요청을 연달아 보낸 값이다. 메모리가 꽉 찬 맥에서 한동안 쉰 뒤의 첫 요청은 훨씬 느릴 수 있다(`backend/model/README.md`).

## 어댑터를 쓸지 정하는 기준 (시험용을 돌리기 전에 적음)

학습한 어댑터는 아래를 모두 채울 때만 쓴다. 하나라도 어긋나면 학습 없는 구성을 유지한다.

1. 시험용 증상: 맞은 문항 수가 학습 없는 구성 이상이고, 급한 코드를 놓친 문항이 늘지 않는다.
2. 시험용 기분: 범위 안 문항 수가 학습 없는 구성 이상이다.
3. 시험용 설명: 판단 보류가 늘지 않고, 검증기 첫 통과가 2문항 넘게 줄지 않는다.
4. 필드별 일치(손으로 쓴 문장, 다섯 필드 모두 일치)가 학습 없는 구성보다 5문항 넘게 많다. 1~3이 같으면 이 항목이 유일한 이득이다.

문항 수가 적어 한두 문항 차이는 우연일 수 있다. 그래서 "같거나 낫다"가 아니면 바꾸지 않는 쪽으로 정했다.
