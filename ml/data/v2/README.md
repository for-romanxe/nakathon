# 학습셋 v2 (2026-11-14 행사 중 작성)

`python3 ml/data/build_v2.py`가 아래 재료를 mlx-lm chat 형식으로 조립해 `train.jsonl` · `valid.jsonl`을 만든다(둘은 저장소에 넣지 않는다. 시드가 고정이라 다시 만들면 같다).

| 재료 | 수 | 어떻게 만들었나 |
|---|---|---|
| 템플릿 증상 문장 | 600 | `../gen_symptoms.py`. 문구를 조합하고, 라벨은 문장에 들어간 표현으로만 정한다 |
| `symptom_natural.jsonl` | 520 | AI(Claude)가 새로 쓴 증상 문장과 라벨. 부정·남의 증상·지나간 증상·관용 표현·한영 혼용 포함 |
| `mood.jsonl` | 300 | AI(Claude)가 새로 쓴 기분 문장과 척도. 문장이 말하지 않은 척도는 기본값(기분 3, 피로 2, 스트레스 2) |
| `explain_targets.jsonl` | 283 | `explain_inputs.jsonl` 300개에 지금 구성(Gemma 4 12B, 학습 없음)이 쓴 답 가운데 검증기를 통과하고 첫 후보를 고른 것 |

- 지시문은 서비스 코드(`backend/model/client.py`)에서 가져온다. 학습과 서비스의 프롬프트가 어긋나지 않는다.
- 열에 하나(170개)는 학습에 쓰지 않고 떼어 둔다. `ml/eval/run_fields.py`가 이 문장들로 필드별 일치를 잰다.
- 평가셋 v2와 같은 문장은 없다(`ml/eval/run_eval2.py --check`). 시험 전용 지식 문단은 설명 입력에 쓰지 않았다.
- 설명 답은 사람이 쓴 정답이 아니다. 증상·기분을 학습하는 동안 설명 능력이 달라지지 않게 붙잡는 용도다.

## 라벨을 얼마나 믿을 수 있나

- 기분 300문장: 다른 AI 채점자가 라벨을 모른 채 다시 채점했고, 문장이 말한 척도 590칸 가운데 589칸이 같았다. 그 뒤 42문장은 표현을 다듬었다(33문장은 다시 눈가림 확인, 9문장은 작성자만 확인).
- 증상 520문장: 170문장을 다른 AI 채점자가 같은 라벨 규칙으로 눈가림 채점했고, 다섯 필드 모두 일치가 169/170이었다. 이 세트의 작성 작업은 파일을 쓴 뒤 마무리 보고 전에 중단돼, 작성자의 자체 검수 기록이 없다. 형식·중복·평가셋 겹침은 기계로 확인했다(문제 0건).
- 채점자는 모두 같은 계열 모델이고 각 1회다. 규칙을 일관되게 따랐다는 근거이지, 사람이 봐도 맞다는 근거는 아니다. **사람이 아직 읽지 않았다.**
- 눈가림 채점자가 어색하다고 본 것: 일상 단어까지 영어로 섞은 한영 혼용 문장("meal 먹고", "neck이").

## 학습

```sh
cd ml && .venv/bin/python train_v2.py -c train_v2.yaml      # 모델 서버를 먼저 내린다 (메모리)
```

`train_v2.py`는 mlx-lm 학습에 한 가지를 고친 것이다. Gemma 4는 생각을 끄면 답 바로 앞에 빈 생각 칸을 붙이는데, mlx-lm의 학습용 템플릿 호출은 이를 붙이지 않아 학습과 서비스의 입력이 어긋난다. 여기서는 서버와 같은 호출로 프롬프트를 만든다.
