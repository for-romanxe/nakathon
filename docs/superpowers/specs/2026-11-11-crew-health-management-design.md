# Crew Health · 관리 플랫폼으로 재구성 (설계, 2026-11-11)

회의 논의용 목업(`mockup/app/`)에 반영할 내용. 제출물 아님. 제출용은 11/14 09:00 이후 새로 제작.
근거 노트: `notes/iss-crew-health-routine.md`(실제 ISS 루틴·출처), `notes/product-shape-brief.md`(시나리오 S1–S9), `PRODUCT.md`, `DESIGN.md`.

## 1. 의도와 이유
- 지금 목업은 **계기판**이다. 상태는 알려주지만 "오늘 뭘 하라"가 직관적으로 안 온다(제목이 진단문, 큰 글자가 숫자, 할 일은 스크롤 밖).
- 바꿀 방향은 **승무원이 이미 하는 건강 루틴을 한곳에서 가볍게 돌리는 관리 플랫폼**. 아침에 이름을 부르고, 오늘 할 일을 먼저, 수치는 그 근거로.
- 챌린지 본문이 직접 권한다: "미션 루틴의 일부로 측정·행동을 프롬프트", "측정법·지표·위험을 설명", 클릭 가능한 인체, 색 코딩, 시간 차트.
- 레퍼런스: 현대 AI 헬스케어 미러(인사 + 오늘의 생활 습관 가이드 + 몸 그림 + 수치). 온기 있는 컨시어지 톤.

## 2. 목표 / 비목표 / 실패 조건
- 목표: 승무원 A가 아침에 열면 10초 안에 "오늘 이렇게 한다"를 안다. 이상이 없는 날에도 화면이 할 말이 있다.
- 비목표: 수분 섭취 기록(실제 요구사항에 없음), 점수·배지·순위형 게임화, 실제 모델 실행.
- 실패 조건: 과하게 문제로 만드는 것. 지표 하나가 하루 벗어났다고 노란 배너가 뜨면 실패. 체크인이 30초를 넘으면 실패.

## 3. 결정된 내용 (사용자 결정 · 표시 없는 것은 사용자 결정)
### 3.1 오늘 화면 구조 (위에서 아래로)
1. 인사 + 날짜: "좋은 아침입니다, 승무원 A님." Sol·시각. (저녁엔 "오늘 하루 수고했어요" 식으로 바뀜 — 내 판단)
2. 오늘 상태 한 문장 + 색. 정상이면 초록 "기준선 안입니다. 평소대로." 주의면 노랑, 경보면 빨강(경보는 전체 화면 인터럽트가 우선).
3. **오늘의 가이드 (화면의 주인, 가장 큰 영역)**. 항목마다 세 조각: `목표 · 오늘의 조정 · 왜(출처 cite)`. 조정이 없으면 목표만.
   - 운동 2.5시간: 밴드로 자동 집계된 분/목표. 주의 상태면 "오늘은 저강도 1시간 · 심박 +40 이내" + 이유.
   - 수면 평가: 아침 체크인 결과. 밴드 수면 시간 자동 + 승무원 질 평가.
   - 기분·피로 눈금: 체크인 결과 표시.
   - 측정 날 항목(해당 날만): 주간 식이 설문, 주간 PMC(비행의 면담) 준비 요약, 월간 체질량, 분기 활력징후(체온·혈압·맥박·호흡).
   - 임시 항목(이벤트에서 생김): "14:00 기립 시 어지러움 재확인" 등.
   - 참고 한 줄(3.4): 색·배지 없이 가이드 안에 한 줄.
4. 근거: 지표 6 타일(기존) + 작은 바디. 크기를 줄여 아래로.
5. 오늘 이벤트(기존).
6. 체크인 연속 일수 하나만 작게. (게임화는 이것뿐 — 내 판단)

### 3.2 체크인 리듬 (실제 ISS 루틴에서 가져옴)
- **아침 체크인, 30초**: 시스템이 먼저 채우고 사람은 확인만. 수면 질 1~5(한 번 탭), 기분·피로 눈금 두 개, 증상은 "없음"이 기본이고 "있어요"를 누르면 증상 대화로. 완료하면 오늘의 가이드가 확정된다.
- **저녁 체크아웃, 선택**: 운동 자동 확인, 스트레스 눈금, 증상.
- **주 1회, 2분**: 식이 설문(짧게), PMC 전 주간 요약(수면 7일·벗어난 지표·이벤트) 자동 생성 → 확인.
- **월 1회 / 분기**: 체질량, 활력징후 입력 화면. 측정 날은 시스템이 띄움.
- 원칙: 시스템이 먼저 채우고 사람은 틀렸을 때만 고친다. 하루 입력 예산 5분 안.

### 3.3 몸 상태가 루틴을 바꾼다
- 조정은 **규칙**이 정한다(코드). 이유 문장은 **모델**이 쓴다. **검증 코드**가 숫자·출처·판정 일치를 확인한다. 정상인 날은 설명을 만들지 않는다.

### 3.4 경보 계층 (과하게 문제로 만들지 않기)
- **참고(advisory)**: 지표 하나가 하루 벗어남. 색·배지 없음. 가이드에 한 줄 "참고로 심박이 평소보다 약간 높아요. 지켜볼게요."
- **주의(caution)**: 이틀 연속 벗어남 **또는** 지표 2개 이상 **또는** 증상과 함께. 노란 상태 문장 + 레일 배지. 인터럽트 없음.
- **경보(warning)**: 증상 규칙(흉통·호흡곤란 등) 또는 ±3σ. 전체 화면, 모델 건너뜀. 종결에 이유 필수.
- 설명은 규칙 판정보다 세게 말할 수 없다(검증 "판정 일치"). 무시(override)는 이유를 고르게 하고 기록.

### 3.5 증상이 있을 때 위험 안내 = 세 줄
1. 위험 범주 (HRP 분류: 심혈관 적응, 체액 이동, 수면·피로, 행동 건강, 방사선, 영양 등)
2. 가능한 상태 이름 — **기기 안 고정 목록에서만** 고른다(NASA ExMC 허용 의료 상태 목록 방식). 항상 "가능성" 표현. "입니다" 금지.
3. 오늘 할 일 (출처 cite)
- 검증 규칙 "범위"는 "진단명 없음" → "**목록 밖 이름 없음 + 단정 표현 없음**"으로 바꾼다.

### 3.6 디자인 성격 변경
- DESIGN.md의 "정밀한 계기판, 색은 이상일 때만"을 버린다. "아침마다 말 거는 관리자". 초록이 정상을 뜻해도 되고 인사·온기가 들어간다. 토큰(색·폰트·반경)은 유지, 성격·규칙 문단을 고쳐 쓴다.
- 여전히: 평평함, 헤어라인, 카드 중첩 금지, 출처는 파랑 cite, 숫자는 모노.

### 3.7 유지하는 것
- 몸·추세·기록(증상 대화)·절차서·승무원(CMO)·설정·이벤트 상세·경보 화면과 S1–S9 흐름. 말투와 가이드 연결만 새 성격에 맞춘다.
- 증상 대화의 결과 메시지는 3.5의 세 줄 형식으로 바꾼다.

## 4. 제약
- 정적 HTML/CSS/JS, 빌드 없음, `mockup/app/` 안에서. 상태는 localStorage(`crewhealth.v1` → 스키마 바뀌면 `v2`로 키 올리고 기본값 재생성).
- 가상 데이터·가상 문서임을 화면에 계속 표시. 의료 조언 아님.
- 모든 화면은 헤드리스로 렌더·스크린샷·콘솔 0 오류 확인 뒤 완료 처리.

## 5. 빌더에게 맡기는 것
- 가이드 항목의 시각 형태(행인지 카드인지), 체크인 화면이 모달인지 페이지인지(제안: 오늘 화면 위에 올라오는 첫 진입 시트), 주간·월간 입력 화면의 위치(제안: 기록 탭 안).
- 고정 상태 목록의 구체 항목(10개 내외, 가상이되 그럴듯하게: 기립성 저혈압, 우주 멀미, 탈수, 수면 부족, 두통(CO2), 근골격 통증, 상기도 감염, 피부 발진, 안압 상승 의심, 불안·기분 저하).
- 밤 사이 데이터·연속 일수·측정 주기 계산의 가상 구현.
