# Crew Health 발표 구성과 시연 대본

기준: 발표 준비 시점의 `main` (`b681135`). 아래 4분은 리허설용 배분 예시이며 실제 발표 제한에 맞춰 조정한다.

| 순서 | 시간 | 화면과 발표 대사 |
| --- | ---: | --- |
| 1. 문제 | 20초 | **화성 기지 3D 인트로.** “몸이 평소와 다른데 지상 의료팀의 답을 바로 받을 수 없다면, 승무원은 지금 무엇을 확인할 수 있을까요?” 화면에 ‘기내에서 바로 확인’과 ‘지상에 보내고 답을 기다림’을 나눈다. 시연 설정은 편도 12분, 왕복 전파 시간만 24분이다. |
| 2. 해결책 | 25초 | **실제 앱 전체 화면.** “Today에서 오늘의 변화, Body와 Trends에서 부위와 추세, Log와 Procedures에서 증상 기록과 원문 근거를 확인합니다.” 3D Body는 지표를 보여주는 화면이다. 모델이 신체 부위를 진단한다고 설명하지 않는다. |
| 3. 실제 사용 데모 | 115초 | **아래 시연 순서대로.** 아침 체크인, 개인 기준선과 비교, 증상 보고, 확인 질문, 설명의 출처, 근거가 없을 때의 판단 보류까지 한 이야기로 보여준다. |
| 4. 데이터와 구현 | 30초 | “지금 화면의 측정값은 합성 시연 데이터입니다. 규칙 엔진이 개인 기준선과 수치를 비교하고 경고 단계를 정합니다. 기내에서 실행하도록 설계한 소형 언어 모델(SLM)은 증상 보고를 정리하고, 제공된 문단으로 설명을 작성합니다.” NASA 자료는 실제로 사용한 위치와 함께 표기한다. |
| 5. 검증·한계 | 35초 | “설명에서 수치, 출처 ID, 경고 단계, 응답 형식, 단정 표현을 검사합니다. 검사에서 실패하면 한 번 다시 만들고, 그래도 실패하면 판단을 보류합니다.” 지상 전송은 대기열 또는 사전 녹화로 짧게 보여준다. |
| 6. 마무리 | 15초 | “지상 답변을 기다리는 동안에도, 승무원은 무엇이 달라졌고 그 판단이 어떤 기록에 근거하는지 기내에서 확인할 수 있습니다.” |

## 메인 데모: 근거가 있는 경우와 없는 경우

1. **C1 · Today → 아침 체크인.** 수면·기분·피로를 직접 기록한다. “웨어러블이 심박이나 수면 같은 신호를 보여줘도, 증상의 원인이나 내가 어떻게 느끼는지까지 알 수는 없습니다.” 혈압은 현재 측정 항목으로 소개하지 않는다.
2. **Today → Trends.** 초기 시연 데이터에서 C1의 안정 시 심박은 73 bpm, 개인 기준선은 68 bpm이다. 화면에 나온 값을 읽고 Trends에서 이전 기록과 비교한다. 실제 앱에 없는 자유 질문 채팅이나 그래프 자동 확대는 시연 동작으로 설명하지 않는다.
3. **Log → 증상 보고.** 예시 입력: “어지러워요.” 화면에서 기립 시 더 어지러운지 묻는 확인 질문을 보여준다. 검토된 관련 문단이 연결된 환경에서는 설명이 표시되면 출처를 눌러 **Procedures의 해당 번호 문단**을 열고, 표시되는 확인 항목을 짚는다.
4. **두 번째 보고: 관련 근거 없음.** 보고에 맞는 문단이 없는 입력을 리허설에서 골라 둔다. “측정값과 기록은 표시하지만, 기내 자료로 설명할 수 없어 판단을 보류합니다.” Today의 **왜요?** 버튼은 가이드에 인용된 문단을 그대로 보여주는 기능이다. 문단이 없으면 답변을 보류하며, 자유 질문에 답하는 채팅과는 구분한다.
5. **선택 장면: C2 → Crew 전송 대기열.** 시간이 있으면 전송 → 수신 누락 표시 → 다음 통신 창 → 같은 번호로 재전송 → 수신 확인을 보여준다. 시간이 짧으면 대기열 화면 한 장으로 대신한다.

## 발표 화면에 붙일 데이터·검증 표기

- **측정값:** 저장소의 합성 시나리오. NASA가 측정한 우주비행사 개인 기록으로 소개하지 않는다. 한국어·영어 근거 문단을 보여줄 때는 실제로 연결한 문서의 기관, 제목, URL, 문단 ID를 함께 표시한다.
- **검증:** 수치 검사, 출처 ID 존재 검사, 단계 검사, JSON 형식 검사, 단정 표현 검사. 출처 ID가 유효하다고 해서 그 문단이 답변의 의미까지 뒷받침한다는 보장은 없다. 평가 결과를 넣을 때는 모델·평가셋·검사 범위를 붙인다. 검증기 통과율을 임상 정확도나 실제 긴급 경고 성공률로 표시하지 않는다.
- **실행 모드:** 기본은 모의 모델이다. 검토된 근거 문서가 미설정이면 실제 백엔드의 절차 문서 목록은 비어 있다. 실모델과 근거 문서를 연결하고 외부 인터넷을 끈 상태로 같은 흐름을 확인했다면 그 화면 또는 측정 결과를 넣는다. 확인하지 않았다면 ‘기내 실행을 목표로 설계’라고 설명하고, 녹화나 모의 모델 화면은 그 사실을 표시한다.
- **심리 상태:** 체크인에 기분과 피로를 직접 기록할 수 있다. 앱의 긴급 규칙이 감지한 표현은 기내에서 먼저 경고를 표시한다. 한 시간은 설명용 상황이며, 상담 제공·자동 연락·모든 긴급 표현 감지를 구현했다고 말하지 않는다.
- **약 안내:** 현재 데모에서 모델이 약이나 용량을 추천하지 않는다. 검토된 절차서의 원문을 조건에 맞춰 안내하는 것은 확장 방향이며, 응급 시 약 기능 잠금 해제를 구현했다고 소개하지 않는다.
- **통신:** 지상 모델에 의존하면 통신 지연과 연결 중단의 영향을 받는다. 모델 크기가 패킷 손실을 일으키지는 않는다. 앱은 순번·SHA-256 해시 저장과 수신 확인·재전송 흐름을 로컬에서 시뮬레이션한다. 해시는 내용 동일성을 확인하는 데 쓰일 수 있으며, 누락 데이터를 복원하지 않는다. 신호 비교 역시 모의 실험이며 실제 우주 전송, 오류 정정이나 운용 성능 검증은 하지 않았다.
